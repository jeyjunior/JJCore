JJCORE 2.1.0 - DATA FIXES AND APPLICATION-ASSIGNED KEYS

Context
This release fixes data integrity issues in generated inserts and updates, adds support for primary keys assigned by the application, and removes a vulnerable transitive dependency from the SQL Server provider. No public API was removed or renamed.

Security
- JJCore.Infra.Data.SqlServer references System.Security.Cryptography.Pkcs 9.0.21 directly.
- Microsoft.Data.SqlClient 7.0.0 resolves Pkcs 8.0.1 or 9.0.13, which are affected by CVE-2026-84008 (GHSA-846f-f764-76mx).
- Version 9.0.21 satisfies every Microsoft.Data.SqlClient target, so .NET Framework, .NET 8, .NET 9, and .NET 10 consumers restore without package downgrade errors (NU1605).

Dates
- JJCore no longer generates dates. Previously, an unfilled DateTime (DateTime.MinValue) was replaced with DateTime.UtcNow in inserts and updates.
- A null DateTime? and an unfilled DateTime are written as NULL in inserts, batch inserts, and updates.
- An unfilled DateTime marked with RequiredFieldAttribute throws before the command runs.
- Columns filled by database defaults should use EditableAttribute(false) so JJCore does not send them.

Primary Keys
- PrimaryKeyAttribute.DatabaseGenerated was added. The default value is true and preserves the existing behavior.
- When DatabaseGenerated is false, the key is included in inserts and batch inserts, and AddReturningAsync returns the assigned value.
- A key that is not filled (null, Guid.Empty, or an empty string) throws before any command runs. Batch inserts validate every entity before the first insert.
- On SQL Server, AddReturningAsync casts SCOPE_IDENTITY() to the key type: bigint for long, uint, and ulong keys; smallint, tinyint, and decimal for their respective types; int otherwise.
- SQL Server identity values above Int32.MaxValue no longer overflow. Int32 keys still return Int32.
- When the database returns no generated key, the error message no longer claims that no row was inserted and points to DatabaseGenerated = false.

SQLite
- Bracketed identifiers are no longer removed from SQLite queries. SQLite supports them natively, so columns named with reserved words, such as Order, work in generated queries.
- Brackets inside string literals and GLOB patterns in custom SQLite queries are preserved.

Transactions
- UnitOfWork.Commit preserves the original exception when the rollback that follows a failed commit also fails. AsyncUnitOfWork already had this behavior.

Documentation
- AddBatchAsync documentation states that the generated INSERT statement is executed once per entity.
- AddAsync and AddReturningAsync documentation states that the returned key can be generated by the database or assigned by the application.
- README documents primary key generation and date handling.

Behavior Changes
- Applications that relied on unfilled DateTime properties receiving the current UTC date must assign the value or use a database default with EditableAttribute(false). NOT NULL columns without a value now fail with the database error.
- UpdateAsync writes NULL for unfilled DateTime properties instead of the current UTC date.
- On SQL Server, AddReturningAsync returns Int64 for uint and ulong keys instead of Int32.

Validation
- dotnet build JJCore.sln -c Release completed with 0 warnings and 0 errors.
- No vulnerable packages were reported for the solution or for net48, net8.0, net9.0, and net10.0 consumers.
- Insert, batch insert, update, date, key, and transaction scenarios were verified against SQLite and SQL Server LocalDB.
- PostgreSQL and MySQL were not verified against a live server in this release.

Publication
All generated packages are written to artifacts/packages, which can also be used as a local NuGet source for validation.
Publish JJCore.Domain and JJCore.Infra.Data.Core before the provider packages. Publish JJCore.Infra.Data.PostgreSQL, JJCore.Infra.Data.SqlServer, JJCore.Infra.Data.SQLite, and JJCore.Infra.Data.MySQL before the aggregate JJCore.Infra.Data package.
