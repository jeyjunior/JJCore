JJCORE 2.3.0 - CORRECTNESS FIXES, GENERATED KEYS, TYPE HANDLING, AND RAW SQL

Context
This release fixes the defects found by the consumer test projects for SQLite, SQL Server, PostgreSQL, and MySQL. It includes the fixes prepared for 2.2.1, which was not published. Existing code keeps compiling, except in the rare cases listed under Compatibility. Read Behavior Changes before upgrading: some fixes change results that code may depend on.

Fixes
- UpdateAsync: when the primary key is not named Id and the entity also has an ordinary property named Id, the key value was written into the Id column without any error. The key now uses its own parameter name, which never matches a written property.
- Generated keys: AddReturningAsync and AddAsync now read keys that the database generates without IDENTITY or AUTO_INCREMENT.
  - SQL Server: Guid and string keys generated by a default, such as NEWID(), are read with OUTPUT INSERTED ... INTO a table variable, which also works on tables with triggers. Before, SCOPE_IDENTITY() returned NULL and the call failed after the row had been inserted. Numeric keys still use SCOPE_IDENTITY().
  - SQLite: keys are read with INSERT ... RETURNING. Before, last_insert_rowid() returned the internal rowid, so a string key generated by a default returned 1, 2, and so on without any error. Requires SQLite 3.35 or later; the bundled SQLite is newer.
  - MySQL: MySQL can only return AUTO_INCREMENT values. A Guid or string key generated by a default or trigger now throws InvalidOperationException before the insert. Before, AddReturningAsync returned 0 or, on an open connection, the key of another row inserted earlier in the session, without any error. LAST_INSERT_ID() is reset before the insert, so a numeric key that does not come from AUTO_INCREMENT throws instead of returning another row's key.
  - When no key is returned, the message says that the row may already have been saved.
- AddReturningAsync returns the generated key converted to the type of the key property. Before, the type depended on the driver: UInt64 on MySQL and Int64 on SQLite for any key type.
- AddAsync throws before the insert when the key cannot be returned as int: an application-assigned key that does not fit, such as a Guid, a non-numeric string, or a long above int.MaxValue, and a database-generated key of a type that never converts, such as Guid. Before, the row was inserted and the conversion failed afterwards.
- SQLite: Guid properties could be written but not read, because Microsoft.Data.Sqlite stores Guid values as text. JJCore registers a Dapper type handler on the first SQLite operation, unless the application already registered a Guid handler. The handler reads Guid and text values only; Guid values stored as BLOB are not converted, because their byte order depends on the tool that wrote them.
- SQLite: SQLitePCLRaw.bundle_e_sqlite3 was updated from 2.1.12 to 2.1.14. The .NET Framework targets of 2.1.12 copied a win-arm native file that does not exist in the package, so .NET Framework projects without a RuntimeIdentifier, such as class libraries and test projects, failed with MSB3030. NuGet reports no vulnerability for 2.1.12 or later.
- SQL Server: AddAsync, AddReturningAsync, AddBatchAsync, and UpdateAsync failed with error 257 when a byte[] property was null, because NULL was sent as nvarchar. NULL byte[] values are now sent as binary on SQL Server.
- SQL Server: inserts and updates send DateTime values as datetime2. Before, SqlClient sent them as the legacy datetime type: values were rounded to 1/300 second even in datetime2 columns (10:00:00.123 was stored as 10:00:00.1233333), and dates before 1753 failed in the client.
- Transactions: commands that receive a transaction that was committed, rolled back, or ended by the server now throw InvalidOperationException before they run. On SQL Server, after an error with SET XACT_ABORT ON or a deadlock, SqlClient ran the following commands outside the transaction, so Rollback did not undo them.
- Cancellation: GetListAsync(condition, token), GetByConditionAsync(condition, token), GetAsync(condition, token), and ExecuteQueryAsync(query, token) bound to the overloads without cancellation, and the token was used as the parameters object. The token is now honored, including calls through IRepository<TEntity> and ICancellableRepository<TEntity> and code compiled against 2.2.0. If a token is also passed as cancellationToken, both are honored.
- AsyncUnitOfWork: OpenAsync and BeginTransactionAsync now throw OperationCanceledException for a token that is already cancelled. Before, Npgsql returned an idle pooled connection without checking the token, and MySqlConnector started the transaction on net8.0.
- Mapping: indexers caused TargetParameterCountException in every operation, and public static properties were mapped as columns. Both are now ignored. Properties with only a getter body, such as FullName => FirstName + " " + LastName, are no longer mapped. Private setters, init setters, get-only auto-properties, and private setters declared in a base class are still mapped. [Column] keeps a computed property mapped.
- DateTimeOffset.MinValue is written as NULL, like DateTime.MinValue, and [RequiredField] rejects it. Before, it was written as 0001-01-01 or, on PostgreSQL, as -infinity.
- PostgreSQL translator: ARRAY [name] (with spaces), the elements of nested arrays such as ARRAY[[a], [b]], and identifiers directly after a reserved keyword, such as WHERE[Id] and AND[Active], are now handled. Before, the first two were translated to identifiers and failed, and the third was not translated.
- MySQL translator: bracketed identifiers written directly after a word, as in WHERE[Id], and brackets inside executable comments, such as /*!80000 [IsActive] = 1 AND */, are now translated.
- Connections: wrapped connections, such as MiniProfiler's ProfiledDbConnection, could not be used, because JJCore identifies the database by the connection type. They can now be registered with ConnectionFactory.RegisterDatabaseResolver.
- SetPropertyValue: null or DBNull for a non-nullable value type, such as int, returned true and stored 0. It now returns false and keeps the current value.
- ToSql: CRLF and CR line breaks are handled like LF, and lines with only spaces are removed.

New API
- IExtendedRepository<TEntity> (JJCore.Domain.Interfaces.Repository): inherits ICancellableRepository<TEntity> and declares DeleteAsync(object id), DeleteAsync(object id, IDbTransaction?, CancellationToken), the (condition, cancellationToken) overloads, and the RawSql overloads. Repository<TEntity> implements it. IRepository<TEntity> and ICancellableRepository<TEntity> are unchanged.
- RawSql (JJCore.Domain.Models): wraps a condition or command that JJCore sends without translating bracketed identifiers. Use it for SQL that the translator does not handle, such as a PostgreSQL subscript written with a space (tags [i]). Overloads: DapperExtensions GetListAsync, GetByConditionAsync, and ExecuteQueryAsync, and the same methods in Repository<TEntity> and IExtendedRepository<TEntity>.
- Repository<TEntity>.DeleteAsync(object id) and DeleteAsync(object id, IDbTransaction?, CancellationToken): delete by Guid, string, or any key type.
- GetListAsync(condition, cancellationToken), GetByConditionAsync(condition, cancellationToken), and ExecuteQueryAsync(query, cancellationToken) in DapperExtensions, Repository<TEntity>, and IExtendedRepository<TEntity>.
- ConnectionFactory.RegisterDatabaseResolver(Func<IDbConnection, DatabaseType>): identifies the database of connection types that JJCore does not recognize. It is called only for those types and applies to the whole process.
- JJCoreTypeHandlers.ReadDateTimeOffsetAsUtc(): optional. Reads DateTimeOffset properties from columns that return a DateTime without kind, such as MySQL datetime, as UTC instead of local time. It applies to every provider in the process. It does not fix MySQL timestamp columns, which the server converts using the session time zone.

Behavior Changes
- AddReturningAsync returns the key in the type of the key property. Code that casts the result to the driver type breaks: (long)key on SQLite or (ulong)key on MySQL for an int key now throws InvalidCastException. Cast to the key property type, or use Convert.ToInt64. Assert.Equal(1L, key) and similar comparisons also change.
- AddReturningAsync throws InvalidOperationException when the generated key does not fit the key property type, such as a bigint value above int.MaxValue for an int property. The row may already have been saved.
- AddAsync with a Guid key, a non-numeric string key, or a long key above int.MaxValue that is assigned by the application throws before the insert, so the row is no longer saved. A Guid key generated by the database also throws before the insert.
- SetPropertyValue(instance, name, null) on a non-nullable value type returns false and keeps the value. Code that used it to reset a property to 0 must pass the default value instead.
- MySQL: AddAsync and AddReturningAsync with a Guid or string key generated by the database throw before the insert. Code that called AddAsync only to insert, ignoring the returned 0, must use [PrimaryKey(DatabaseGenerated = false)] with a key generated by the application, or AddBatchAsync.
- MySQL: a numeric key generated by a default or trigger throws after the insert instead of returning 0 or another row's key. LAST_INSERT_ID() of the session is 0 after such an insert.
- Transactions that are no longer usable throw InvalidOperationException from JJCore instead of the provider exception.
- SQL Server: DateTime values in inserts and updates are datetime2 parameters. Columns of type datetime, smalldatetime, and date are converted by the server, which rounds once instead of twice; values close to a rounding limit can be stored differently. For example, 23:59:59.9999999 in a date column was stored as the next day and is now stored as the same day, and 10:00:29.999 in a smalldatetime column was stored as 10:01 and is now stored as 10:00. Dates before 1753 in a datetime column are rejected by the server (error 242) instead of by the client. DateTime values stored in text or sql_variant columns are converted from datetime2, so their text format or base type changes.
- A cancelled token passed as in GetListAsync(condition, token) now throws OperationCanceledException instead of being ignored. AsyncUnitOfWork.OpenAsync throws for a cancelled token even when the connection is already open.
- Computed properties without [Column] are no longer written. A computed property that maps to a real column, such as Slug => Title.ToLower(), needs [Column] to keep being written. A property with an explicit getter over a private field and no setter is also treated as computed. A public static property is no longer written to or read from a column.
- DateTimeOffset.MinValue is written as NULL and fails in NOT NULL columns.
- PostgreSQL: ARRAY [x], the elements of ARRAY[[a], [b]], and WHERE[Id] are translated differently, as described under Fixes. In the first two cases the old output was rejected by the server, and in the third it was sent unchanged and also rejected.
- MySQL: WHERE[Id] and brackets inside /*! ... */ are translated. Before, they were sent unchanged and rejected by the server.
- ToSql output changes for input with CRLF or CR line breaks and for lines with only spaces.
- SQLite: the Guid type handler is registered for the whole process on the first SQLite operation.
- The NotSupportedException message for an unrecognized connection type now mentions RegisterDatabaseResolver.
- Projects that reference SQLitePCLRaw.bundle_e_sqlite3 below 2.1.14 directly receive NU1605 (package downgrade). Update that reference to 2.1.14 or remove it.

Compatibility
- Calls written as GetListAsync(default), GetByConditionAsync(default), or ExecuteQueryAsync(default) on DapperExtensions or Repository<TEntity>, with the default literal as the first argument, become ambiguous between the string and RawSql overloads and no longer compile. Pass null or an empty string instead. Through IExtendedRepository<TEntity>, the same calls compile and bind to the RawSql overload.
- Classes derived from Repository<TEntity> that already declare DeleteAsync(object, ...), GetListAsync(string, CancellationToken), GetByConditionAsync(string, CancellationToken), ExecuteQueryAsync(string, CancellationToken), or the RawSql overloads with the same signature receive warning CS0114, which fails the build with TreatWarningsAsErrors. Add override, or new, to those members.

SQLite On .NET Framework
- An AnyCPU .NET Framework executable runs as 64-bit, but the SDK copies only the x86 native SQLite library, so the first connection fails with "Library e_sqlite3 not found". The same happens with Microsoft.Data.Sqlite alone, and it already happened with JJCore 2.2.0. Set PlatformTarget to x64, or a RuntimeIdentifier such as win-x64, in the executable project. The README documents this.
- xUnit test projects on .NET Framework also need shadowCopy disabled, or a RuntimeIdentifier, because shadow copying moves the test assembly away from the native library.

Known Limitations
- PostgreSQL: a bracket after a space and a name, a closing parenthesis, or a quoted identifier is translated as an identifier, because it cannot be told apart from an alias without AS, such as FROM [Customers] [c]. A subscript written with a space, such as dezenas [i], becomes dezenas "i". Remove the space or use RawSql.
- AddAsync with a long or string key generated by the database can only check the value after the insert, so it still throws after the row is saved when the value does not fit an int.
- MySQL: DateTimeOffset values in datetime columns are still read as local time unless JJCoreTypeHandlers.ReadDateTimeOffsetAsUtc() is called. MySQL timestamp columns are converted by the server using the session time zone.
- MySQL: deadlocks, DDL statements, and COMMIT inside procedures end the transaction without notifying MySqlConnector, so JJCore cannot reject the following commands. PostgreSQL turns COMMIT after a failed command into a rollback without an error. Roll back after any error inside a transaction.
- Only Microsoft.Data.SqlClient, Microsoft.Data.Sqlite, Npgsql, and MySqlConnector are tested. Other drivers registered with RegisterDatabaseResolver, such as MySql.Data or System.Data.SqlClient, may convert types or handle transactions differently. MariaDB is not tested.
- The README section "Database Behaviors" lists driver and database behaviors that JJCore does not change.

Publication
All generated packages are written to artifacts/packages, which can also be used as a local NuGet source for validation.
Publish JJCore.Domain and JJCore.Infra.Data.Core before the provider packages. Publish JJCore.Infra.Data.PostgreSQL, JJCore.Infra.Data.SqlServer, JJCore.Infra.Data.SQLite, and JJCore.Infra.Data.MySQL before the aggregate JJCore.Infra.Data package.
